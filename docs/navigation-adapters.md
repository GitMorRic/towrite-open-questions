# Open the displayed location with one button

## V1 flow

```text
ESP32 polls desired
  → physical eink refresh completes
  → ESP32 ACKs the displayed tuple
  → main-button single click
  → POST /api/v1/device/events
  → ToWrite validates token, event ID, and displayed tuple
  → local target resolution
  → start/resume the displayed task when needed
  → the registered adapter opens the exact Obsidian location or explicit HTTPS target
```

Commands always act on acknowledged `displayed`, never a newer `selected`
card that has not reached the pixels yet.

The same start/resume-before-open behavior applies on both Overview and Task
pages. A task that is already running is opened without creating another timer
transition.

Daily targets resolve in this order:

```text
explicit towrite-target
  → task's own link
  → nearest ancestor-group link
  → task ^daily_* block
  → Today Dashboard
```

Question cards try stable block ID, contextual text anchor, then last-known
line. A deleted heading/block is reported as missing instead of silently
opening the top of the file.

## Test without a physical button

After a device or simulator has completed one poll, render, and display ACK,
run `ToWrite: Device: simulate main-button single click` from Obsidian's
command palette. The diagnostic still uses the acknowledged displayed tuple;
it does not bypass the display guard.

## ESP32 essentials

Use `examples/esp32s3-eink/` and configure:

```cpp
const char* API_BASE_URL = "http://DESKTOP_LAN_IP:48321";
const char* DEVICE_TARGET_ID = "target id from ToWrite";
const char* DEVICE_TOKEN = "that target's scoped token";
const int MAIN_BUTTON_PIN = 6; // choose pins for the actual board
```

The sample pins default to `-1`, which intentionally disables button input.
For LAN access, enable External API, bind it to `0.0.0.0`, and allow the port
through the desktop firewall. Ports 48321 (External API), 48322 (Capture
Bridge), and 8790 (Capture PWA) are different services.

## Adapter architecture

Device and Hub payloads never carry Vault paths, URLs, or executable schemes.
They carry the displayed tuple and opaque refs. The Connector maps the frozen
local snapshot to a versioned `NavigationTarget`, then dispatches it through a
`NavigationRouter`.

V1 registers `ObsidianNavigationAdapter` and a constrained
`WebNavigationAdapter`.

- `web` is accepted only from an explicit local
  `[towrite-target:: https://...]` field. The adapter revalidates HTTPS,
  rejects credentials and executable/non-web schemes, and opens with
  `noopener,noreferrer`. A URL found only in task prose is never executable.
- `provider` remains reserved for a future note-app adapter ID plus stable
  resource/location IDs.

The local checkpoint store can prepend a contextual text anchor and a
last-known line to an Obsidian target. It is written only after the user
chooses **Later**, and is never placed in a Hub or device payload. External web
pages cannot report their scroll position to Obsidian; use a stable URL
fragment for V1.

Other note applications should use immutable page/block IDs where possible.
Official deep links must be generated by an explicitly enabled local adapter,
not accepted verbatim from a device. This keeps the button protocol stable
while preventing arbitrary URI execution.
