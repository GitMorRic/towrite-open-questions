# ToWrite 墨水屏 Alpha：宣传、招募与视频脚本

## 统一表述

一句话：

> 一块只显示当前下一步的实体屏幕。按一下，电脑回到相关笔记和原文；双击后手机只打开这张卡片，让我快速记录而不进入信息流。

事实边界：

> ToWrite 软件、2.7 英寸预览、设备协议和模拟器已经可用；真实硬件正在开发，目前不是可购买的成品。

许可证统一写作“源码可见，个人和非商业用途按 PolyForm Noncommercial 免费”，不要称为“开源硬件/开源软件”。

## 首批要找的两类人

**最痛用户**：每天在电脑上用 Obsidian，同时推进多个项目，经常找不到任务对应原文，又不想为了记一句话打开手机信息流的人。

**共创者**：能刷 ESP32、愿意记录接线/日志/功耗并提交可复现问题的 e-ink DIY 用户。他们帮助硬件成熟，但不能替代付费痛点验证。

暂不招募纯手机 Todo 用户、企业团队和只想购买成品的人。

## 小红书四帖

### 1. 痛点与软件

标题：`我把 Obsidian 日记改成了每天只显示一个下一步`

内容顺序：项目很多 → 每次重新找上下文 → 今日页只选当前下一步 → 点击回原文 → 软件可用、硬件尚在做。结尾只问“你最常在哪一步丢上下文？”。

### 2. 实体屏概念

标题：`如果 Todo 不在手机里，而在一块 2.7 寸墨水屏上？`

展示桌面距离、屏幕刷新和按键，不用纯 UI mockup。明确按钮到电脑依赖 Obsidian 已运行和局域网。

### 3. 失败日志

标题：`为什么墨水屏已经换任务，按钮却可能打开上一条？`

用 desired → 物理刷新 → displayed ACK → 按键解释问题，并展示断网或刷新失败时保留旧卡片。附控制器、驱动、刷新耗时和残影照片。

### 4. 招募

标题：`找 20 位每天用 Obsidian、愿意折腾 ESP32 的人共测`

写清入组条件、要投入的时间、硬件是否自备、日志范围、隐私边界、已知限制和退出方式。不要用抽奖或诱导互动。

## Reddit / Obsidian 社区

`r/ObsidianMD` 标题：

> I built a local-first physical next-action display for Obsidian — one button opens the exact note and line

正文先讲工作流和失败案例，再讲 Markdown 真源、opaque ID 和 displayed ACK，最后放 GitHub；账号先正常参与讨论，不让首帖成为裸推广。

`r/esp32` 只在真实硬件可运行后发。必须包含屏幕控制器、板卡、引脚、库版本、BOM、功耗、刷新耗时、字体策略和失败经验。

`r/eink` 从“实体下一步是否比通用仪表盘更有用”提问，重点征求尺寸、按钮和残影反馈。

Obsidian Forum `Share & Showcase` 作为长期主帖，维护安装、隐私、限制、兼容性和更新日志。

## 30–45 秒短视频分镜

| 时间 | 画面 | 旁白/字幕 |
| --- | --- | --- |
| 0–4 秒 | 多项目、多标签页，停下来寻找 | “我不是没任务，我是找不到从哪里继续。” |
| 4–10 秒 | 真实墨水屏只显示一项 | “所以桌面上只保留当前下一步。” |
| 10–18 秒 | 手按主键，电脑跳到原文位置 | “按一下，回到对应笔记和原文。” |
| 18–27 秒 | 双击，手机收到通用通知，点开录音/文字 | “双击只打开眼前这张卡，不进入信息流。” |
| 27–35 秒 | Markdown 与 ACK 流程近景 | “本地优先，Markdown 是真源；屏幕刷新成功才认。” |
| 35–45 秒 | 原型、接线与招募条件 | “硬件还在开发，招 20 位 Obsidian/ESP32 用户共测。” |

必拍真实手指、屏幕物理刷新和电脑精确跳转。通知锁屏画面使用演示文案，不显示真实任务。

## 4–6 分钟长视频提纲

1. 为什么普通 Todo 丢失原文上下文；
2. ToWrite 当前软件形态和 Markdown 真源；
3. 卡片选择、desired/displayed 与错误目标防护；
4. 三键映射和 `eventId` 幂等；
5. 命名桌面动作为什么只允许本机白名单；
6. Web Push 为什么只能通知点开，不能强制手机抢前台；
7. 真实硬件仍缺控制器确认、字体、配网、OTA 和功耗数据；
8. 测试者需要做什么、会收集什么、绝不收集什么。

## Alpha 入组表字段

- 每周使用 Obsidian 的天数和操作系统；
- 典型项目数量、最痛的上下文丢失场景；
- 是否有 ESP32/e-ink 经验、是否可自备或组装硬件；
- iOS/Android 与是否愿意安装主屏 PWA；
- 每周可反馈时间；
- 是否同意提交去敏诊断、刷新照片与延迟数据；
- 如果稳定可用，愿付价格区间及成立条件；
- GitHub/论坛联系方式和退出测试方式。

不要收集 Vault 内容、Wi-Fi 凭据、设备 token、精确地理位置或与验证无关的个人信息。
