# ToWrite 墨水屏 Alpha：硬件落地与验收

这份文档是首批 ESP32-S3、264×176、2.7 英寸横屏原型的执行清单。仓库目前已经提供协议、三键状态机、display ACK、设备能力上报和失败关闭的屏幕驱动边界，但**没有假定具体屏幕控制器**。在控制器、载板和引脚确认前，不得复制某个 Waveshare 或 GxEPD2 示例后宣称支持。

## 1. 首周必须锁定的硬件事实

给每个候选样机拍摄正反面并记录：

- 面板丝印、FPC 丝印、控制器或载板 SKU；
- ESP32-S3 开发板 SKU、Flash/PSRAM 容量；
- SPI 的 BUSY、RST、DC、CS、CLK、DIN 引脚与电平；
- 供电路径、USB 常供电电流、电池型号、充电与保护芯片；
- 三个实体按键的 GPIO、上拉方式和是否与启动绑带脚冲突；
- 驱动库版本、全刷/局刷能力、黑白或多色能力；
- 实测分辨率与旋转方向。

确认结果写入 `examples/esp32s3-eink/towrite-panel-driver.h` 的真实实现，并把 `SCREEN_MODEL` 改为可追溯型号。默认模板返回 `false`，所以不会把串口日志错误地 ACK 为物理显示。

## 3. 屏幕驱动契约

`towrite-panel-driver.h` 的实现必须满足：

1. `begin()` 只有在控制器初始化和基础自检通过时返回 `true`。
2. 卡片先在内存排版，中文字体缺字、截断和换行在刷新前完成。
3. `renderCard()` / `renderEmpty()` 只有在物理刷新结束后返回 `true`。
4. 刷新失败保留旧画面并返回 `false`；上层不会发送 ACK，也不会允许按键。
5. `renderStatus()` 只更新窄状态区；不得让五秒轮询触发整屏全刷。
6. 驱动维护局刷次数，达到阈值后执行一次全刷清残影；阈值来自实测，不写死为营销数字。

中文字体使用按演示 Vault 生成的字形子集，并为未收录字符显示明确占位符。发布包要记录字体来源和许可证。

## 4. 配网、凭据与恢复

Alpha 可以先用编译期 Wi-Fi 验证屏幕；交付测试者前必须完成 BLE Provisioning 或 SoftAP 二选一：

- 设备凭据写入 NVS，不写串口、不进入崩溃日志；
- 每块屏幕使用独立 target-scoped token，不烧录 External API 管理员 token；
- 长按隐藏的恢复键或明确组合键 10 秒后恢复出厂；
- 配网失败显示短错误码，串口输出可导出的诊断，不显示 SSID/密码/token；
- 首版要求 Obsidian 正在运行且电脑与屏幕处于可路由的同一局域网。

## 5. 固件交付门槛

在称为“可交付 Alpha”前完成：

- 签名 OTA、升级失败回滚、当前/上一版本号；
- 看门狗、Wi-Fi 断线指数退避、NVS 迁移版本；
- ACK 上报 `firmwareVersion`、`screenModel`、`capabilities` 和可选电量；
- 刷新中锁定按键；重启后没有 ACK 就不复用旧 tuple；
- USB 常供电下测按钮到电脑动作延迟；电池模式另测，不由理论值外推；
- 导出最近 100 条去敏诊断事件。

## 6. 稳定性测试表

| 测试 | 数量/条件 | 通过标准 |
| --- | --- | --- |
| 刷新—ACK—单击 | 连续 500 次 | 0 次打开错误目标 |
| 重复 `eventId` | 每类动作 20 次 | 只产生一次副作用 |
| 未 ACK 按键 | 20 次 | 全部拒绝 |
| 刷新中按键 | 20 次 | 不提交旧/新混合 tuple |
| Wi-Fi 断开与恢复 | 30 个周期 | 保留旧画面，恢复后重新同步 |
| 局刷残影 | 按真实阈值循环 | 记录照片与清屏时刻 |
| OTA 中断 | 10 次 | 自动回滚到可启动版本 |
| 低电量 | 分档实测 | 不产生半刷新后错误 ACK |

测试记录至少包含固件版本、屏幕型号、供电方式、时间戳、HTTP 状态和照片编号。
