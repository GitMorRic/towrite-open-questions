# ToWrite × 墨水屏：90 天 Alpha 看板

目标不是在 90 天内预售硬件，而是验证“实体当前下一步 → 一键回到电脑上下文 → 手机快速记录”的闭环，并留住 20–50 名合适的测试者。

## 当前实现基线

已进入仓库：

- `[towrite-action:: action-id]` 命名桌面动作；优先级高于现有目标、任务链接、父分类、任务 block 和今日页；
- 本机动作白名单支持今日页、专注布局、Vault 内目标、HTTPS 和用户明确批准的应用深链接；不支持 Shell、可执行文件参数和任意路径；
- ESP32 desired/displayed ACK、事件幂等、三键手势和固件/屏幕/能力上报；
- 五分钟短 handoff、冻结 displayed tuple、一次成功写入后失效；长期 token 不再进入 handoff 地址栏；
- PWA Web Push 订阅接口、通用锁屏提醒、点击打开 handoff、IndexedDB 离线保稿；
- 未识别屏幕时失败关闭的 `towrite-panel-driver.h` 驱动边界。

仍然明确缺少：

- 已识别并实测的真实屏幕驱动、中文字体包和残影策略；
- BLE/SoftAP 配网、NVS、OTA、回滚、电量与功耗数据；
- 实际部署的 Device Hub Web Push 服务。仓库只定义 Connector/PWA 契约，Hub 必须实现相应端点；
- 新用户五分钟配对、外壳和 14 天真实日用记录。

## 周期与完成定义

### 第 1–2 周：真实硬件闭环

- 完成硬件识别表、接线图和可复购 BOM；
- 实现 `towrite-panel-driver.h`，显示中文当前卡片；
- 测量完整刷新、局刷、联网和按钮到电脑动作的时间；
- 完成第一轮 500 次自动/人工组合测试；
- 访谈 5 名每天使用 Obsidian 的开发者、研究者或创作者。

完成定义：真实像素刷新后才 ACK；任何失败都不允许按钮命中未显示卡片。

### 第 3–4 周：电脑动作与手机入口

- 用设置页创建并验证命名动作；
- 部署 Device Hub 的 Web Push config、subscription 和 phone-handoff 接口；
- iOS 主屏 PWA、Android Chrome、通知拒绝、NFC/二维码回退各走通一次；
- 形成扫码、配网、授权、测试按键的五分钟脚本。

完成定义：锁屏不泄露任务正文；点击通知看到的是双击时冻结的卡片；一次写入后 handoff 重放返回拒绝。

### 第 5–6 周：可交付 Alpha

- OTA/回滚、恢复出厂、诊断导出、兼容性表；
- 外壳和按键原型；
- 作者连续使用 14 天；
- GitHub Discussion、Bug 模板、测试者入组表和隐私说明。

### 第 7–8 周：5–10 人封测

- 入组者每天使用 Obsidian，愿意刷固件并每周反馈；
- 每周只处理前三类高频故障；
- 跟踪使用天数、按钮次数、失败原因、误打开数和愿付价格。

### 第 9–12 周：20–50 人扩展

- 发布真实硬件短视频、刷机教程和技术复盘；
- 分开招募“最痛用户”和“ESP32/e-ink 共创者”；
- 只有稳定性和留存达标后才评估 PCB、预售或原生 App。

## 指标与记录方法

| 指标 | 门槛 | 数据来源 |
| --- | --- | --- |
| 错误目标打开 | 500 次中为 0 | eventId + displayed tuple 去敏日志 |
| 局域网按钮延迟 | 中位数 <1 秒，P95 <2 秒 | 固件 occurredAt 与 Connector 完成时间 |
| 手机通知延迟 | 中位数 <3 秒 | Hub handoff 与 SW push 时间 |
| 首次安装 | 15 分钟内 | 观察记录，不由作者代操作 |
| 激活 | ≥20 人 | 完成首次显示、ACK 和按键 |
| 四周留存 | ≥10 人每周使用 ≥3 天 | 只收聚合使用日，不收笔记正文 |
| 付费意愿 | ≥5 人明确报价区间 | 访谈原话与条件 |

## 决策闸门

- 少于 30% 测试者需要 Obsidian 冷启动：继续要求 Obsidian 已运行，不做托盘 Connector。
- 通知权限拒绝率高：优化 NFC/二维码，不以原生 App 掩盖定位问题。
- 错误目标打开不为零：停止扩招，先修 displayed/事件链路。
- 只有“很酷”但无四周使用：不做 PCB 和预售，回到用户痛点与卡片选择。
